 THE 5 SCORING ALGORITHMS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 🔴 CVSS v3.1-INSPIRED (0-10)
   ├─ Industry standard severity with context
   ├─ Accounts for: Authentication code, production status, admin impact
   ├─ High score = Critical severity in important context
   ├─ Use for: Real-world risk assessment
   └─ Example: 9.2 = Plaintext password in auth.py

2. 📊 WEIGHTED AGGREGATE (0-100)
   ├─ Traditional "start at 100, lose points" approach
   ├─ Deducts: Critical(-40), High(-25), Medium(-12), Low(-5)
   ├─ Adjusted by: Finding confidence scores
   ├─ Use for: Intuitive pass/fail grading
   └─ Example: One high finding deducts 25 points (score 75, grade B+)

3. 🎯 RISK LEVEL (Critical/High/Medium/Low/Info)
   ├─ Threshold-based categorical assessment
   ├─ Logic: Worst-case risk determination
   ├─ Output: Simple risk tier + reasoning
   ├─ Use for: Executive summaries, compliance
   └─ Example: "HIGH - 3 high-severity findings present"

4. 📈 CONFIDENCE-WEIGHTED (0-100)
   ├─ Accounts for detection reliability
   ├─ Higher confidence = more impact on score
   ├─ Highlights: Low-confidence findings for manual review
   ├─ Use for: Understanding finding trustworthiness
   └─ Example: 0.95 confidence = Act with confidence

5. 🌐 ENTROPY RISK (0-100 + Distribution)
   ├─ Analyzes finding concentration
   ├─ Shows: Where problems are concentrated
   ├─ Helps: Prioritize remediation efforts
   ├─ Use for: Determining where to focus fixes
   └─ Example: "High concentration in auth.py - fix there first"

 CONTEXT MULTIPLIERS (How location affects severity)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Location              Multiplier  Impact
────────────────────────────────────────
Authentication code   1.4x        Higher severity
Production code       1.3x        Higher severity
Admin-related code    1.5x        Highest severity
Test/Demo code        0.3x        Lower severity
Config files          1.1x        Slightly higher

Example: 
Plaintext password = 9.0 base
In auth.py (1.4x) × in production (1.3x) = 9.0 × 1.82 = 16.4 → capped at 10.0

 TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q: Why is my score lower than expected?
A: Check confidence levels. Low-confidence findings reduce score less.

Q: What does "concentrated" mean?
A: Findings in few files (easy to fix) vs spread across many (systematic).

Q: Can I ignore low-confidence findings?
A: No. Manually verify them - they may indicate real issues.

Q: How often should I scan?
A: After code changes. Quarterly minimum. Pre-deployment mandatory.

Q: Which algorithm matters most?
A: The primary score is based on finding severities and counts. Read all five algorithms for supplementary context.
